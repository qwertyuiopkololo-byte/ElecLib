# Тема 2. Задание 3. Реализация пользовательского интерфейса

Для реализации пользовательского интерфейса в приложении ElecLib были разработаны **HTML-шаблоны** (Thymeleaf), настроены **стили оформления** в CSS, а также реализованы **контроллеры** Spring MVC для обработки действий пользователя. Интерфейс построен как **веб-приложение**: страницы открываются в браузере, навигация выполняется по ссылкам в верхнем меню, формы отправляются методами GET и POST.

В рамках практики особое внимание уделено экранам **трёх новых функций**: комиксы (PDF), оглавление в текстовой читалке и обложки в каталоге. Схемы и макеты — в [`figures/eleclib-assignment-3.drawio`](figures/eleclib-assignment-3.drawio).

## Общая компоновка страниц

На рисунке 12 представлена разметка **базового макета** приложения — файл `layout.html` и подключаемый фрагмент `fragments/header.html`.

Макет содержит:

- **шапку** (`<header class="header">`) с логотипом и навигацией по разделам: Книги, Жанры, Избранное, **Комиксы**, Полки, Статистика, Подписка; для администратора — пункт «Админ»;
- **основную область** (`<main class="main">`) для содержимого конкретной страницы;
- **подвал** (`<footer class="footer">`);
- блоки уведомлений `alert success` / `alert error` при успехе или ошибке операции.

Главная навигация заменяет в мобильных шаблонах практики компонент `BottomNavigationView`: пользователь переходит между разделами по ссылкам в одной строке меню. Для гостя отображаются только «Вход» и «Регистрация».

*Рисунок 12 — Схема макета `layout.html` (Draw.io, вкладка «12 - Layout»).*

## Форма добавления книги, комикса и обложки (админ)

На рисунке 14 представлен экран **создания и редактирования книги** — шаблон `admin/book-form.html`. Экран объединяет настройку **двух новых возможностей** каталога:

- поле **URL обложки** (`coverUrl`) — ссылка на изображение; при пустом значении в каталоге показывается заглушка;
- галочка **«Комикс»** и блок загрузки **файла PDF** (`enctype="multipart/form-data"`, поле `pdfFile`).

Также предусмотрены поля названия, описания, текста книги (для обычных книг), выбор автора и жанра, кнопка «Сохранить». JavaScript на странице скрывает блок PDF, если комикс не выбран, и снимает обязательность поля «Текст» для комикса.

Обработку формы выполняет **`AdminController.saveBook()`**: сохранение записи в Supabase и вызов `ComicPdfStorageService.store()` при загрузке PDF.

*Рисунок 14 — Схема формы администратора (Draw.io, вкладка «14 - Admin kniga»).*

*Рисунок 15 — Фрагмент полей обложки и комикса в `book-form.html`.*

```html
<label>URL обложки</label>
<input type="url" th:field="*{coverUrl}" placeholder="https://example.com/cover.jpg"/>

<label class="checkbox-label">
    <input type="checkbox" name="comic" value="true" th:checked="${book.comic}"/>
    Комикс (PDF загружается на сервер)
</label>
<input type="file" name="pdfFile" accept="application/pdf,.pdf"/>
```

## Каталог книг: обложки и поиск

На рисунке 16 представлен экран **каталога книг** — `books/list.html`. Пользователь видит:

- строку **поиска** по названию или автору (`search-bar`, параметр `q`);
- сетку карточек **`book-grid-covers`** с обложками пропорции 2∶3.

Каждая карточка подключается из фрагмента **`fragments/book-card.html`**: при наличии `coverUrl` выводится `<img class="book-cover-img">`, иначе — **`book-cover-placeholder`** с первой буквой названия. Для комиксов в метаданных карточки отображается метка **PDF**.

Данная вёрстка обеспечивает наглядный каталог и единообразное отображение текстовых книг и комиксов.

*Рисунок 16 — Схема каталога с обложками (Draw.io, вкладка «16 - Katalog»).*

*Рисунок 17 — Условный вывод обложки в `book-card.html`.*

```html
<img th:if="${book.coverUrl != null && !#strings.isEmpty(book.coverUrl)}"
     class="book-cover-img" th:src="${book.coverUrl}" .../>
<div th:if="${book.coverUrl == null || #strings.isEmpty(book.coverUrl)}"
     class="book-cover-placeholder">
    <span class="book-cover-letter" th:text="...">А</span>
</div>
```

## Раздел «Комиксы» и читалка PDF

На рисунке 18 представлен экран списка **`comics/list.html`**: сетка карточек комиксов с кнопками «Читать», «В избранное» (действие `actions='comic'` в фрагменте карточки). Если PDF ещё не загружен, кнопка «Читать» недоступна (`comicReady`).

На рисунке 19 представлена **читалка комикса** — `books/read-comic.html`:

- панель навигации по **страницам PDF** (предыдущая / следующая, поле номера страницы);
- область **`comic-canvas-wrap`** с элементом `<canvas>` для отрисовки страницы библиотекой **PDF.js**;
- панель **закладок** по номеру страницы PDF.

PDF загружается с адреса `/books/{id}/comic.pdf`. Позиция чтения сохраняется через `POST /books/{id}/reading-position`.

## Текстовая читалка с оглавлением

На рисунке 20 представлен экран **чтения текстовой книги** — `books/read.html`.

Интерфейс включает:

- панель перелистывания **виртуальных страниц** текста;
- кнопку **«Оглавление»**, открывающую панель `reader-toc-panel`;
- список пунктов **`toc-list`**: для каждого `ReaderTocEntryDto` — заголовок раздела и кнопка **«Перейти»** (JavaScript переводит читалку на нужную страницу);
- сообщение, если заголовки в тексте не найдены.

Дополнительно на экране доступны закладки, заметки и настройки оформления читалки (шрифт, тема).

*Рисунок 20 — Читалка с оглавлением (Draw.io, вкладка «20 - Oglavlenie UI»).*

*Рисунок 21 — Разметка панели оглавления в `read.html`.*

```html
<div class="reader-toc reader-toc-panel" id="readerToc">

    <ul id="tocList" class="toc-list">
```

## Контроллеры обработки действий

| Контроллер | Действия интерфейса |
|------------|---------------------|
| **BookController** | Каталог, страница книги, `read()` / `read-comic.html`, отдача PDF, сохранение позиции чтения |
| **ComicController** | Страница `/comics` — список комиксов |
| **AdminController** | Форма книги, загрузка обложки (URL) и PDF |
| **FavoriteController**, **BookMarkController** | Кнопки на карточках и в читалке (избранное, закладки) |

Данные для шаблонов передаются через **Model** (`books`, `tocEntries`, `bookCard`, `user` и др.).

## Использование стилей и оформления

Для единого визуального оформления используется файл **`src/main/resources/static/css/style.css`** (аналог `themes.xml`, `colors.xml` и `styles.xml` в Android-проекте).

Стили позволяют централизованно управлять:

- **цветовой схемой** — фон `#f5f3ef`, шапка `#2c3e50`, акцентные кнопки `#3498db`;
- **сеткой каталога** — классы `.book-grid`, `.book-grid-covers`, `.book-card`;
- **обложками** — `.book-cover-img`, `.book-cover-placeholder`, `.book-cover-letter`;
- **комиксами** — `.comic-badge`, `.comic-admin-fields`, `.reader-container-comic`, `.comic-canvas-wrap`;
- **читалкой и оглавлением** — `.reader-nav`, `.reader-toc-panel`, `.toc-list`;
- **формами и кнопками** — `.btn`, `.btn.secondary`, `.alert`, `.search-bar`.

Использование общего CSS обеспечивает согласованный дизайн всех страниц ElecLib.

Пример правил для обложек:

```css
.book-cover-img { width: 100%; aspect-ratio: 2 / 3; object-fit: cover; }
.book-cover-placeholder {
    aspect-ratio: 2 / 3;
    background: linear-gradient(145deg, #5d6d7e, #2c3e50);
}
```
