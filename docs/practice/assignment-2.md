# Тема 1. Задание 2. Формирование алгоритма работы приложения ElecLib

В приложении ElecLib были реализованы **три функции**:

1. **Чтение комиксов в формате PDF** (загрузка администратором, раздел «Комиксы», читалка на PDF.js).
2. **Оглавление в текстовой читалке** (автоматический поиск заголовков и переход к разделу).
3. **Обложки книг в каталоге** (URL обложки или заглушка с буквой названия).

Блок-схемы — в файле [`figures/eleclib-assignment-2.drawio`](figures/eleclib-assignment-2.drawio).

---

## Алгоритм работы с комиксами (PDF)

*Рисунок 7 — Блок-схема действий пользователя (Draw.io, вкладка «7 - Komiksy»).*

### Добавление комикса (администратор)

1. Нажать в меню **«Админ»** → **«Книги»** → **«Добавить»** или **«Изменить»**.
2. Включить **«Комикс»**, выбрать файл **PDF**, указать название, автора и жанр.
3. Нажать **«Сохранить»** — комикс появится в каталоге.

### Чтение комикса (читатель)

1. Открыть раздел **«Комиксы»** или на карточке книги нажать **«Читать»**.
2. Если не выполнен вход или нет подписки — войти в аккаунт или оформить подписку.
3. Если PDF ещё не загружен администратором — показывается сообщение об этом.
4. Листать страницы кнопками **«Предыдущая»** / **«Следующая»**.
5. При необходимости открыть **«Закладки»** и добавить закладку на текущей странице.

---

## Алгоритм формирования и использования оглавления

*Рисунок 8 — Блок-схема действий в текстовой читалке (Draw.io, вкладка «8 - Oglavlenie»).*

**Алгоритм работы (читатель):**

1. Открыть карточку **текстовой** книги и нажать **«Читать»**.
2. Откроется страница читалки с текстом книги.
3. Нажать кнопку **«Оглавление»** — сбоку или сверху появится список разделов.
4. **Если разделы найдены** — выбрать нужный пункт и нажать **«Перейти»**; откроется соответствующая страница текста.
5. **Если разделов нет** — показывается сообщение: «Заголовки разделов в тексте не найдены».
6. Дальше читать книгу, листая **«Предыдущая»** / **«Следующая»** или вводя номер страницы.

## Алгоритм отображения обложек книг

*Рисунок 9 — Блок-схема действий с обложками (Draw.io, вкладка «9 - Oblozhki»).*

### Настройка обложки (администратор)

1. **«Админ»** → **«Книги»** → создать или изменить книгу.
2. В поле **«URL обложки»** вставить ссылку на картинку в интернете или оставить пустым.
3. Нажать **«Сохранить»**.

### Просмотр в каталоге (читатель)

1. Открыть **«Книги»**, **«Избранное»** или **«Полки»**.
2. **Если у книги есть обложка** — на карточке видно фото.
3. **Если обложки нет** — цветная заглушка с **первой буквой** названия.
4. Нажать на карточку, чтобы открыть описание книги или начать чтение.

## Описание структуры данных

Для хранения информации по **трём реализованным функциям** используются объектные модели данных, объекты передачи данных (DTO) и файлы на диске сервера. Ниже перечислены только структуры, относящиеся к комиксам, оглавлению и обложкам.

*Рисунок 10 — схема моделей трёх функций (Draw.io, вкладка «10 - Modeli»).*

### 1. Чтение комиксов (PDF)

**Модель Book** — в таблице `books` для комикса задаётся поле **`contentType`** со значением `comic` (для обычной книги — `text`). Хранятся название, автор, жанр и метаданные; поле **текста** для комикса не используется.

**Модель ReadingPosition** — предназначена для сохранения **номера последней страницы PDF**, которую просмотрел пользователь (`lastPage`, `updatedAt`).

**Модель BookMark** — используется для закладок в комиксе: привязка к книге, пользователю и **номеру страницы PDF**.

**BookCardDto** — объект для карточки в разделе «Комиксы» и каталоге: признаки **`comic`** (это комикс) и **`comicReady`** (PDF уже загружен на сервер).

Файл **PDF** в Supabase не хранится. На диске сервера лежит `data/comics/{book_id}.pdf`; работа с ним выполняется сервисом **`ComicPdfStorageService`** (не модель БД).

### 2. Оглавление в текстовой читалке

**Модель Book** — поле **`text`** содержит полный текст книги; по нему при открытии читалки строится оглавление.

**ReaderTocEntryDto** — пункт оглавления: **заголовок раздела** (`title`) и **номер виртуальной страницы** (`pageNumber`). Отдельной таблицы в базе нет: список формируется в памяти утилитой **`ReaderToc`** из текста книги.

Разбиение текста на страницы (~2500 символов) выполняет утилита **`ReaderPaging`**; номер страницы для каждого заголовка вычисляется по позиции символа в тексте.

### 3. Обложки книг в каталоге

**Модель Book** — поле **`coverUrl`** (колонка `cover_url` в Supabase) хранит **ссылку HTTPS** на изображение обложки. Если поле пустое, в интерфейсе показывается заглушка.

**BookCardDto** — передаёт **`coverUrl`** в шаблон карточки каталога, избранного и полок; шаблон **`book-card.html`** решает, вывести `<img>` или блок с первой буквой названия.

Сам файл изображения на сервер ElecLib **не загружается** — только URL; браузер загружает картинку по внешней ссылке.

## Основные методы

*Рисунок 11 — методы трёх функций (Draw.io, вкладка «11 - Metody»).*

### 1. Комиксы (PDF)

**ComicPdfStorageService** — `store(bookId, pdfFile)` сохраняет PDF после админки; `hasPdf(bookId)` проверяет файл на диске; `asResource(bookId)` отдаёт PDF в читалку.

**AdminController.saveBook()** — при галочке «Комикс» и выборе файла устанавливает `contentType = comic` и вызывает `store()`.

**BookController** — `read()` открывает `read-comic.html` для комикса; `comicPdf()` отдаёт PDF пользователю с подпиской.

**BookService** — `findComicsAsCards()` формирует список для `/comics`; `toCardDtos()` заполняет в карточках поля `comic` и `comicReady`.

### 2. Оглавление

**ReaderToc** — `build(text)` возвращает список `ReaderTocEntryDto`; `matchesTocLine()` распознаёт строку-заголовок; `pageForCharOffset()` вычисляет номер страницы.

**ReaderPaging** — `splitIntoPages(text)` и `totalPages(text)` делят текст на виртуальные страницы для читалки и оглавления.

**BookController.read()** — для текстовой книги вызывает `ReaderToc.build(book.getText())` и передаёт `toc` в шаблон `read.html`.

### 3. Обложки

**AdminController.saveBook()** — записывает `coverUrl` в модель `Book` при создании и редактировании.

**BookService.toCardDtos()** — копирует `coverUrl` из книги в `BookCardDto` для каталога и раздела комиксов.

**Шаблоны** `fragments/book-card.html` и `books/detail.html` — по наличию `coverUrl` выводят изображение или заглушку с буквой названия.

## Используемые принципы ООП

Принципы проиллюстрированы на **трёх новых функциях** приложения.

**Инкапсуляция** — тип книги (`contentType`) и адрес обложки (`coverUrl`) хранятся в модели `Book`; доступ к PDF на диске скрыт в `ComicPdfStorageService`, контроллер не работает с путями файлов.

**Разделение ответственности** — оглавление строит `ReaderToc`, страницы текста считает `ReaderPaging`, обложку рисует шаблон `book-card`, данные для карточки готовит `BookService`.

**Полиморфизм** — одна модель `Book` описывает текст и комикс; `BookController.read()` выбирает `read.html` с оглавлением или `read-comic.html` с PDF.

**Абстракция** — карточка каталога использует только `BookCardDto` (`coverUrl`, `comic`, `comicReady`), не зная, откуда загружена обложка и где лежит PDF.
